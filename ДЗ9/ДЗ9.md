## Задача 1.1.

1. Метод принимает List<IDamageable> тк это позволяет работать со всеми объектами который получают урон единообразно. Он позволяет не изменять метод при добавлении новых объектов, это и есть полиморфизм.
2. Допустим false обозначает разрушение после любого урона, ок. Но то что HP неизменно является нарушением контракта интерфейса.Это strange...
3. Нуууу типа зелье реализует только IHealable и если мы уберём ProcessHeal то при List<IDamageable> ошибка на зелье вылетит. 
4. Если мы добавляем в интерфейс поле IsDead то его нужно реализовать во всех классах релизующих IsDamageable. Если это не сделать то будет ошибка компиляции тк это будет являться нарушением КОНТРАКТА


## Задача 1.2 - Сравнение абстрактных классов и интерфейсов

| Утверждение | Abstract class | Interface |
| Может содержать поля с конкретными значениями | + | − |
| Может иметь полноценный конструктор | + | − |
| Один класс может наследовать/реализовывать несколько таких типов | − | + |
| Может содержать реализацию метода по умолчанию | + | + |
| Может объявлять свойства без реализации | + | + |
| Может быть использован как тип поля или переменной | + | + |
| Может наследовать классы | + | − |
| Может содержать приватные методы | + | + |

Дополнительно:

Хз как рисовать текстом. Абстрактный класс будет включать логику и характеристику сущностей, а интерфейсы открывать отдельные возможности определённым классам. Таким образом можно разделить общие и индивидуальные возможности классов.
